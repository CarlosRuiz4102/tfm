
DUDA SOBRE ARQUITECTURA DEL TFM
================================

Contexto:
Estamos diseñando un TFM que consiste en un agente conversacional para análisis financiero mediante 
NL→SQL, detección de patrones y generación de insights.

El usuario podrá hacer preguntas en lenguaje natural y el sistema deberá:
- obtener datos financieros usando yfinance
- almacenarlos en una base de datos SQL
- consultarlos mediante NL→SQL
- analizarlos automáticamente
- detectar patrones en los datos
- generar insights financieros explicativos


Idea principal del proyecto:
- El usuario hace preguntas sobre empresas o mercados financieros.
- El sistema obtiene datos con yfinance.
- Los datos se almacenan en SQL.
- El sistema consulta esos datos mediante NL→SQL.
- El sistema analiza los resultados y detecta patrones.
- El agente devuelve insights explicados al usuario.

Ejemplo de pregunta del usuario:
"¿Qué tal ha ido Nvidia en los últimos 5 años?"


Duda planteada:
¿Necesitamos un LLM especializado en finanzas y además un sistema que convierta lenguaje natural a SQL?
¿O necesitamos dos modelos distintos: uno financiero y otro NL→SQL?



RESPUESTA / ACLARACIÓN DE ARQUITECTURA
======================================

No es necesario tener dos modelos separados (uno financiero y otro para NL→SQL).
Lo recomendable es construir un AGENTE con un LLM general que utilice herramientas.

La arquitectura se basa en un LLM que actúa como orquestador y utiliza diferentes módulos del sistema.


Estructura del sistema:

1. LLM Orquestador
   Interpreta la pregunta del usuario y decide qué herramientas utilizar.

2. Normalización financiera
   Convierte elementos de la pregunta en variables estructuradas:
   - Empresa → ticker (ej: Nvidia → NVDA)
   - Periodo temporal → rango de fechas
   - Tipo de pregunta → métricas o análisis a realizar

3. Obtención de datos
   Si los datos no están disponibles:
   - Se descargan con yfinance
   - Se almacenan en una base de datos SQL

4. Generación de consulta NL → SQL
   El LLM traduce la pregunta del usuario a una consulta SQL adecuada
   según el esquema de la base de datos.

5. Ejecución de la consulta
   La consulta se ejecuta en la base de datos y devuelve los datos financieros.

6. Análisis financiero y detección de patrones
   Sobre los datos obtenidos se calculan métricas como:
   - retorno total
   - CAGR
   - volatilidad
   - drawdown
   - tendencias temporales
   - comparaciones entre empresas o índices

7. Generación de insights
   El LLM interpreta los resultados y genera una explicación en lenguaje natural
   con los insights más relevantes para el usuario.



Flujo completo del sistema:

Usuario
  ↓
Pregunta en lenguaje natural
  ↓
LLM (agente orquestador)
  ↓
Normalización financiera (empresa, periodo, tipo de análisis)
  ↓
Obtención de datos (yfinance → SQL)
  ↓
Traducción NL → SQL
  ↓
Ejecución de consulta SQL
  ↓
Análisis financiero y detección de patrones
  ↓
Generación de insights
  ↓
Respuesta al usuario



Módulos opcionales del proyecto:

1. Análisis de sentimiento de noticias
   - Modelo: FinBERT
   - Clasificación: Positive / Neutral / Negative
   - Permite analizar el sentimiento del mercado sobre una empresa.

2. Predicción de precios
   - Modelos simples como ARIMA o Prophet
   - Predicciones a corto plazo (ej. 30 días)
   - Módulo exploratorio adicional.



Conclusión:

No es necesario utilizar un LLM exclusivamente financiero para el sistema principal.

Un LLM general que funcione como agente y utilice herramientas (SQL, análisis de datos,
detección de patrones y visualización) es suficiente para construir el sistema.

La especialización financiera se introduce mediante:

- el diseño del esquema de la base de datos
- las métricas financieras implementadas en el análisis
- la detección de patrones en los datos
- modelos especializados como FinBERT para el análisis de sentimiento.
