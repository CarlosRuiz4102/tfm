EVALUACION POR API: GROQ
========================

Fecha de referencia: 12/05/2026
Proyecto: TFM Financial Multiagent MVP


1. OBJETIVO
-----------

Esta ficha resume la evaluacion inicial del perfil `groq` como primera API LLM
externa conectada al MVP. Groq se probo mediante el cliente compatible con
OpenAI, usando el modelo configurado en el entorno local.

El objetivo no fue delegar el calculo financiero en el modelo, sino comprobar si
Groq podia mejorar la redaccion final a partir de resultados ya calculados por
el pipeline determinista.


2. CONFIGURACION
----------------

Perfil:

LLM_ENABLED=true
LLM_PROFILE=groq
LLM_PROVIDER=openai-compatible

Activacion por fase:

LLM_USE_FOR_PLANNING=false
LLM_USE_FOR_CODEGEN=false
LLM_USE_FOR_INTERPRETATION=true

Modelo de referencia:

GROQ_MODEL=llama-3.3-70b-versatile

La clave API se mantiene en `.env` y no se documenta en el repositorio.


3. CASOS EVALUADOS
------------------

Se ejecutaron los seis casos representativos del MVP:

- growth_nvda.
- compare_nvda_amd.
- overview_aapl.
- returns_qqq_spy.
- risk_qqq_spy.
- technical_aapl.


4. RESULTADO
------------

Tras instalar la dependencia `openai` y permitir acceso de red, Groq completo
correctamente los seis casos.

Resumen:

- growth_nvda: completed, sin warnings.
- compare_nvda_amd: completed, sin warnings.
- overview_aapl: completed, sin warnings.
- returns_qqq_spy: completed, sin warnings.
- risk_qqq_spy: completed, sin warnings.
- technical_aapl: completed, sin warnings.

No se observaron recomendaciones directas de inversion y el modelo respeto las
metricas calculadas por el sistema.


5. OBSERVACIONES
----------------

Groq mejoro la naturalidad de las respuestas finales frente al modo
determinista. La respuesta dejo de ser una frase puramente mecanica y paso a
presentar una explicacion mas fluida para usuario final.

La integracion funciono bien porque Groq encaja directamente con la interfaz
OpenAI-compatible usada en el proyecto.

Se observaron caracteres acentuados mal representados en consola en algunas
salidas, aunque el problema se interpreto como una cuestion de visualizacion o
codificacion del entorno.


6. VALOR PARA EL TFM
--------------------

Groq es una buena primera API operativa para demostrar que el MVP puede funcionar
como sistema hibrido:

- calculo financiero determinista;
- interpretacion final asistida por LLM;
- fallback programatico ante fallo externo.

Su mayor fortaleza en esta fase es la facilidad de integracion y la estabilidad
de la ejecucion completa de los seis casos.


7. CONCLUSION
-------------

Groq funciona como proveedor principal inicial para la fase de interpretacion.
No se recomienda activar todavia planificacion ni generacion de codigo con LLM;
la configuracion mas segura sigue siendo usarlo solo para redactar la respuesta
final a partir de resultados ya calculados.
