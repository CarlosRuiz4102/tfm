\chapter{Anexos}

\section{Ejecución del MVP}

El proyecto puede ejecutarse con perfiles LLM mediante los ejemplos incluidos en el repositorio:

\begin{verbatim}
python run_mvp.py --example growth_nvda
python run_mvp.py --example compare_nvda_amd
python run_mvp.py --example overview_aapl
python run_mvp.py --example returns_qqq_spy
python run_mvp.py --example risk_qqq_spy
python run_mvp.py --example technical_aapl
\end{verbatim}

Además de estos ejemplos funcionales, se prepararon scripts específicos para la evaluación cualitativa, la demostración para cliente y la comparación progresiva entre proveedores LLM:

\begin{verbatim}
python scripts\generate_qualitative_client_demo.py
python scripts\generate_qualitative_demo_report.py
python scripts\evaluate_progressive_llm_scope.py --profiles groq gemini university
\end{verbatim}

La última orden puede restringirse a una muestra concreta de dificultad creciente:

\begin{verbatim}
python scripts\evaluate_progressive_llm_scope.py ^
  --profiles groq gemini university ^
  --cases level_a_nvda_growth level_a_qqq_spy_returns ^
          level_b_qqq_spy_clear_compare ^
          level_c_qqq_spy_professional ^
          stress_visual_qqq_spy_monthly
\end{verbatim}

\section{Configuración de APIs}

Las claves de API se guardan localmente en el fichero \texttt{.env}, que no debe subirse al repositorio. El proyecto asume llamadas LLM en el flujo principal, por lo que no hay variables de activación.

Para activar Groq con \nolinkurl{llama-3.3-70b-versatile}, modelo Llama 3.3 70B Instruct orientado a razonamiento general y baja latencia, la configuración es:

\begin{center}
\nolinkurl{llama-3.3-70b-versatile}~\cite{groqllama33docs,meta2024llama33modelcard,meta2024llama3herd}
\end{center}

\begin{verbatim}
LLM_PROFILE=groq
GROQ_MODEL=llama-3.3-70b-versatile
\end{verbatim}

Para activar Gemini con \nolinkurl{gemini-2.5-flash}, modelo Flash de Gemini 2.5 orientado a rapidez y razonamiento, la configuración es:

\begin{center}
\nolinkurl{gemini-2.5-flash}~\cite{google2025gemini25flashdocs,google2025gemini25report}
\end{center}

\begin{verbatim}
LLM_PROFILE=gemini
GEMINI_MODEL=gemini-2.5-flash
\end{verbatim}

Para activar \nolinkurl{openai/gpt-oss-20b} servido por vLLM en el entorno universitario, modelo abierto de la familia gpt-oss usado por su capacidad de razonamiento, seguimiento de instrucciones y generación de código, el perfil técnico configurado es \texttt{university}:

\begin{center}
\nolinkurl{openai/gpt-oss-20b}~\cite{openai2025gptossmodelcard}
\end{center}

\begin{verbatim}
LLM_PROFILE=university
UNIVERSITY_BASE_URL=https://w1.etsisi.upm.es/vllm/v1
UNIVERSITY_MODEL=openai/gpt-oss-20b
\end{verbatim}

\section{Batería de queries A/B/C}

La batería cualitativa se diseñó para comprobar que el sistema no solo termina la ejecución, sino que adapta la profundidad del análisis a la consulta. Las seis primeras queries corresponden al Nivel A y representan peticiones habituales sin formato especial. Las tres siguientes elevan la exigencia al Nivel B, y las tres últimas obligan a una salida de Nivel C.

\section{Query de estrés visual}

Para forzar al sistema a respetar una estructura concreta se incorporó una query adicional de estrés visual:

\begin{quote}
Compara QQQ y SPY durante 2024 como si fuera un informe para un cliente no técnico. Quiero que me muestres los datos exactamente en cuatro bloques: 1) una tabla resumen con rentabilidad total, volatilidad anualizada, máximo drawdown, mejor mes y peor mes; 2) una tabla ranking mensual indicando que activo ganó cada mes; 3) datos para una gráfica normalizada base 100 de ambos activos; 4) datos para una gráfica de drawdown. Cierra con una conclusión clara, sin recomendar comprar ni vender.
\end{quote}

Esta consulta se eligió porque comprueba simultáneamente comprensión, selección de métricas, generación de código, control de formato, datos para visualización e interpretación final sin recomendación de inversión.

\section{Documentación interna de apoyo}

Durante el desarrollo se conservaron notas técnicas, informes de EDA, fichas de evaluación LLM y documentos metodológicos en Markdown. Estos documentos no sustituyen a la memoria, pero sirvieron como evidencias auxiliares para reconstruir decisiones de diseño, resultados experimentales y limitaciones observadas. En particular, se utilizaron el informe de evaluación cualitativa, las salidas de demostración para cliente, la batería progresiva A/B/C y el informe de amplitud multi-modelo para reforzar las secciones de metodología, implementación, integración LLM, resultados y trabajo futuro.
